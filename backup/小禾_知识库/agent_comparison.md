# OpenClaw vs Hermes vs OpenHuman 比较

## 一句话定位

| 平台 | 定位 |
|------|------|
| **OpenClaw** | 调度器 + 路由器 — 把任务分给对的Agent，做cron定时触发，对接飞书 |
| **Hermes** | 自学习分析Agent — 用技能体系做市场分析、策略研究、方法论打磨 |
| **OpenHuman** | 个人AI助手 — 带UI、带记忆、118个集成开箱即用 |

## 功能对比

| 维度 | OpenClaw | Hermes | OpenHuman |
|------|----------|--------|-----------|
| **开源许可** | ✅ MIT | ✅ MIT | ✅ GNU |
| **上手难度** | ⚠️ 终端优先，需配置 | ⚠️ 终端优先，需技能 | ✅ 桌面UI，几分钟上手 |
| **费用** | BYO模型 | BYO模型 | 一价订阅 + Token压缩 |
| **记忆** | ⚠️ 靠插件 | ✅ 自学习循环 | 🚀 记忆树 + Obsidian |
| **集成数量** | ⚠️ 自己接 | ⚠️ 自己接 | 🚀 118+ OAuth集成 |
| **自动数据同步** | ❌ 无 | ❌ 无 | ✅ 20分钟自动同步到记忆 |
| **搜索/抓取** | ❌ 代码工具 | ❌ 代码工具 | ✅ 内置搜索+抓取+语音 |
| **UI界面** | ❌ 终端 | ❌ 终端 | ✅ 桌面App |
| **定时任务** | ✅ Cron | ✅ Cron | ? |
| **模型路由** | ⚠️ 手动 | ⚠️ 手动 | ✅ 内置 |

## 在我们的架构中各扮演什么角色

```
用户需求
    ↓
OpenClaw (调度器) — 定时触发任务、路由消息到飞书
    ↓
Hermes/小禾 (分析师) — 市场分析、策略研究、知识库维护
    ↓
小C/Claude Code (执行器) — 代码实现、数据管线、回测
```

## OpenHuman 要不要装？

**它的优势对我们有吸引力的点：**
1. 118个内置集成（Gmail/日历/笔记等自动同步）
2. 记忆树（比我们现在的知识库更结构化）
3. Token压缩（省成本）
4. 内置搜索+抓取（就不用装web-search-plus插件了）

**但问题：**
1. GNU许可证比MIT严
2. 早期beta版，稳定性存疑
3. 它定位是"个人助手"，不是"专业分析师"
4. 我们已经有一套跑通的架构了，再加一层叠床架屋

**结论：** 对我们现有架构没有直接替代关系。它是个人助手场景，我们是专业投研分析场景。不装。
