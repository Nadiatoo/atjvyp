# 🧹 记忆文件清理规则
# 版本：2026-04-02 创建
# 目的：确保记忆文件高效、整洁、易维护

## 📋 清理原则

### 1. **价值优先原则**
- 保留：有长期价值的重要认知、经验教训、系统改进
- 删除：临时记录、错误信息、重复内容、无效数据

### 2. **系统化原则**
- 统一：所有文件统一命名格式（YYYY-MM-DD.md）
- 结构：使用标准化模板，便于查找和维护
- 索引：重要内容必须记录到索引系统

### 3. **效率原则**
- 简洁：内容精炼，重点突出，避免冗长
- 易查：通过索引系统快速查找所需信息
- 易维：便于更新和维护

## 📁 文件分类与处理规则

### 第一类：必须保留的文件

#### 1. **重要认知突破记录**
- **标准**：改变了工作方法或思维模式的内容
- **处理**：完整保留，更新到记忆索引
- **示例**：
  - 2026-03-25.md（四大分析框架）
  - 2026-03-28.md（信息感知框架）
  - 2026-03-29.md（EGPS框架）
  - 2026-04-02.md（系统化记忆重构）

#### 2. **关键经验教训记录**
- **标准**：从严重错误中学到的重要教训
- **处理**：保留教训部分，删除过程细节
- **示例**：
  - 数据造假教训
  - 分析质量教训
  - 系统可靠性教训
  - 交流方式教训

#### 3. **系统改进记录**
- **标准**：重要的系统架构或功能改进
- **处理**：保留改进内容和效果，删除技术细节
- **示例**：
  - 彪哥战法版本升级
  - 数据源系统改进
  - 分析框架优化

#### 4. **用户重要要求记录**
- **标准**：用户明确提出的重要工作要求
- **处理**：完整保留，确保落实
- **示例**：
  - "只关心结果"原则
  - "真实数据"要求
  - "具体分析"标准

### 第二类：可以精简的文件

#### 1. **日常工作报告**
- **标准**：日常工作记录，没有重要突破
- **处理**：精简为要点，删除细节
- **保留期限**：保留最近30天，超过的归档

#### 2. **技术实现细节**
- **标准**：具体的技术实现过程
- **处理**：只保留结论和效果，删除过程
- **示例**：
  - 脚本修改过程
  - 配置调整过程
  - 问题排查过程

#### 3. **临时记录**
- **标准**：临时的工作记录或想法
- **处理**：评估价值，有价值的整理，无价值的删除
- **保留期限**：评估后决定

### 第三类：应该删除的文件

#### 1. **错误信息文件**
- **标准**：包含错误数据、错误分析、错误结论
- **处理**：立即删除，避免误导
- **示例**：
  - 使用模拟数据的报告
  - 错误的市场分析
  - 无效的系统配置

#### 2. **重复内容文件**
- **标准**：内容与已有文件重复
- **处理**：保留一份最完整的，删除其他
- **检查方法**：对比文件内容，识别重复

#### 3. **临时备份文件**
- **标准**：临时创建的备份文件
- **处理**：确认主文件正常后删除
- **命名特征**：包含backup、temp、old等字样

#### 4. **不规范命名文件**
- **标准**：不符合YYYY-MM-DD.md格式
- **处理**：重命名为标准格式，或合并到标准文件
- **示例**：
  - 2026-03-29_review.md → 合并到2026-03-29.md
  - 2026-03-30_learning.md → 重命名为2026-03-30.md

## 🔄 清理流程

### 每日清理（工作结束时）
1. **填写每日记录**：使用`daily_template.md`模板
2. **评估今日内容**：判断属于哪类文件
3. **精简内容**：删除无关细节，保留重点
4. **更新索引**：如有重要内容，更新`memory_index.md`

### 每周清理（每周日）
1. **检查本周文件**：检查过去7天的所有文件
2. **合并相关文件**：将相关文件合并
3. **删除临时文件**：删除本周的临时文件
4. **更新索引**：更新本周的重要内容到索引

### 每月清理（每月1日）
1. **整理上月文件**：整理上个月的所有文件
2. **归档旧文件**：将超过3个月的文件归档到backup目录
3. **深度清理**：按照清理规则深度清理
4. **更新索引**：全面更新记忆索引系统

### 季度清理（每季度初）
1. **评估文件价值**：评估所有文件的长时期价值
2. **创建精华摘要**：将重要内容提取到精华摘要
3. **删除低价值文件**：删除低价值或过时文件
4. **优化索引系统**：优化记忆索引的结构和内容

## 📊 文件命名规范

### 标准格式：
- **主文件**：`YYYY-MM-DD.md`（如：2026-04-02.md）
- **模板文件**：`daily_template.md`
- **索引文件**：`memory_index.md`
- **规则文件**：`cleanup_rules.md`
- **备份文件**：`backup/`目录下

### 禁止的命名：
- ❌ 包含空格：`2026 03 25.md`
- ❌ 包含中文：`2026年3月25日.md`
- ❌ 包含特殊字符：`2026-03-25_review!.md`
- ❌ 无日期：`今日记录.md`
- ❌ 缩写：`2026-3-25.md`（必须两位月份和日期）

### 正确的命名：
- ✅ `2026-03-25.md`
- ✅ `2026-12-01.md`
- ✅ `2026-01-15.md`

## 🛠️ 清理工具和方法

### 手动清理步骤：
1. **读取文件**：使用`read`工具读取文件内容
2. **评估内容**：判断文件价值和分类
3. **处理文件**：
   - 保留：不做处理
   - 精简：编辑文件，删除无关内容
   - 重命名：使用`edit`工具修改文件名引用
   - 删除：确认后删除
4. **更新引用**：更新其他文件中的引用

### 自动清理建议：
1. **创建清理脚本**：自动化常见清理任务
2. **设置定时任务**：定期自动执行清理
3. **建立检查机制**：定期检查清理效果

## 📌 特殊情况处理

### 1. **重要但冗长的文件**
- **问题**：文件内容重要但过于冗长
- **处理**：创建摘要版本，保留原文件在backup目录
- **示例**：超过50KB的文件可以考虑创建摘要

### 2. **相关但分散的文件**
- **问题**：相关内容分散在多个文件中
- **处理**：合并到主文件，删除分散文件
- **示例**：同一主题的多个记录文件

### 3. **不确定价值的文件**
- **问题**：不确定文件是否有长期价值
- **处理**：移动到`backup/`目录，标记为待评估
- **保留期限**：在backup目录保留3个月后评估

### 4. **技术细节过多的文件**
- **问题**：技术细节过多，影响阅读效率
- **处理**：创建技术文档单独存放，主文件保留结论
- **位置**：技术文档放在`docs/`或`technical/`目录
